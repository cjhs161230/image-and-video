# 基础功能闭环修复设计

## 目标

先让项目具备安全、可验证的普通图片任务闭环，再继续视频工作流：

1. 媒体访问和删除不能越过项目 `data/` 根目录。
2. API 对资源不存在、状态冲突和请求无效返回稳定的 404、409、422 响应。
3. 独立 Worker 能恢复过期任务、领取图片任务、维持 lease、执行供应商调用并持久化成功或失败状态。
4. Worker 执行期间的暂停和取消不会被完成结果覆盖。
5. FastAPI 提供中文前端；用户可以提交图片任务、查询状态、暂停、继续、取消并查看生成结果。
6. 自动测试不调用真实付费 API。

## 范围

本阶段只闭合普通图片任务和基础前端，不重写视频生成流程。视频任务统一入队、连续帧并行、缺帧合成校验等问题保留为下一阶段，相关 `PLAN.md` 项目退回未完成。

## 架构

### API

- 增加统一业务异常映射，将 `KeyError`、非法状态转换和输入业务校验分别映射到 404、409、422。
- 图片任务查询返回已登记媒体的受控 URL，不暴露本地绝对路径。
- FastAPI 在根路径提供 `frontend/index.html`，并挂载前端静态资源。

### Worker

- 新增可单步测试的 `WorkerRunner`，负责恢复 lease、领取任务、分派处理器和失败落库。
- 心跳在任务执行期间独立运行；停止时可靠结束。
- 当前阶段只分派 `image.generate`，未知任务类型标记失败。
- Worker 入口只负责组装数据库、配置、供应商和 `WorkerRunner`。
- 暂停或取消运行任务后，处理器不得把任务重新标记为完成；已产生但未登记的输出按失败路径清理。

### 媒体安全

- 读取、删除原图和缩略图都使用同一个“已登记且位于 data 根目录内”的路径验证。
- 任一路径越界时不执行文件删除，并保留数据库记录以便人工处理。

### 前端

- 保留原生 HTML/CSS/ES Modules。
- 图片页实现模型、提示词、输出数量、格式和 Matsca 模式输入。
- 提交后轮询任务状态，并提供暂停、继续、取消。
- 完成后通过受控媒体 API 展示结果。
- 设置区域仅展示凭证是否配置，不接收或显示密钥。

## 错误与恢复

- Provider 超时发生在请求已发送后时，任务进入 `needs_attention`，避免自动重复计费。
- 明确的配置错误、4xx 请求错误或本地处理错误进入 `failed`。
- Worker 启动时调用过期 lease 恢复；未发送上游请求的任务重新排队，已发送的任务进入 `needs_attention`。
- 前端显示服务端安全错误摘要，不显示凭证、授权头或完整上游响应。

## 测试

- 单元测试覆盖媒体路径越界、Worker 成功/失败/超时/未知类型、暂停取消竞态。
- 集成测试覆盖业务错误状态码、前端挂载、图片任务从入队到媒体结果的完整本地闭环。
- 前端测试验证真实 API 调用和状态渲染逻辑，不再只检查静态文字。
- 完成后运行 pytest、覆盖率、Ruff、Pyright、ESLint、Prettier、前端测试和秘密扫描。

## 非目标

- 本阶段不调用真实 Matsca、DashScope 或 DeepSeek。
- 不完成视频队列化、片段并行、完整视频前端和 Matsca smoke test。
- 不提交或推送 Git。
